OpenZFS for Windows (user mode)

ZFS datasets as Windows drives, served by the ZfsWinUserMode service through WinFsp. No kernel driver of ours is involved, so this works with Secure Boot on.

WinFsp - Windows File System Proxy, Copyright (C) Bill Zissimopoulos, https://github.com/winfsp/winfsp.

1. What you need

  • WinFsp 2.1 or later. Setup refused to install without it.
  • Disks or image files for a new pool, or an existing ZFS pool (from Linux, FreeBSD, macOS or the kernel-driver edition, exported there first with zpool export).

2. Create or import a pool

This edition has the same administration tools as the kernel-driver edition: the OpenZFS for Windows (user mode) program in the Start menu, zfswin, the ZfsWin PowerShell module, and zpool/zfs. They talk to the ZFS engine inside the ZfsWinUserMode service. From PowerShell as administrator:

# a mirrored pool on two image files
fsutil file createnew D:\pools\a.img 1073741824
fsutil file createnew D:\pools\b.img 1073741824
zfswin pool create tank --mirror D:\pools\a.img D:\pools\b.img -O compression=lz4 --yes
zfswin dataset create tank/data

# or an existing pool
zfswin pool import tank --dir D:\pools

The pool's root and each dataset appear as drives with the file system name ZFS. In this edition a child dataset gets its own drive letter: WinFsp cannot mount a drive inside another WinFsp drive. zfswin mount list shows where each dataset is. Pools and mounts come back by themselves when the service starts, including at boot.

Snapshots, scrubs, properties (compression, dedup, sync, ...), mirror disks, read caches and write logs work as described in the zfswin command reference: zfswin help.

3. Use it

  • Use the drive like any other: Explorer, copy and paste, robocopy, applications.
  • Permissions are real Windows ACLs, stored in the pool the same way the kernel-driver edition stores them. Use Explorer's Security tab or icacls.
  • Alternate data streams work, for example Zone.Identifier and Get-Content -Stream.
  • Snapshots are browsable under .zfs\snapshot\<name>, read-only. zfs set snapdir=visible tank/data also shows .zfs in the listing.
  • Block cloning: zfswin clone <source> <target> copies a file instantly by sharing its blocks. Windows' own clone call (FSCTL_DUPLICATE_EXTENTS_TO_FILE) cannot reach a WinFsp file system, so Explorer and copy still copy the data.

Writes are safe on disk after an application flushes, after a write-through write, or once the service stops. That is the same promise as any Windows drive. A power cut does not corrupt the pool: ZFS is always consistent on disk.

4. Unmount and move the pool

zfswin pool export tank

This unmounts the pool's datasets and exports it, so you can take the disks or image files to another computer. Stopping the service (Stop-Service ZfsWinUserMode) does the same for every pool, but they come back when it starts again.

5. Mount configuration by hand

Mounts live under HKLM\SOFTWARE\OpenZFS for Windows\UserMode\Mounts, one key per dataset. Keys named auto-… are made by zfs mount and zpool import. The program's User mode tab edits them. A key with a Source (image folder, image file or device) also imports its pool:

$key = "HKLM:\SOFTWARE\OpenZFS for Windows\UserMode\Mounts\tank"
New-Item -Force $key | Out-Null
Set-ItemProperty $key Source     'D:\pools'          # folder or image file; empty for a pool the service already imports
Set-ItemProperty $key Pool       'tank'
Set-ItemProperty $key Dataset    'tank/data'
Set-ItemProperty $key MountPoint 'Z:'                # a free drive letter, or a folder path that does not exist yet
New-ItemProperty $key -Name ReadOnly -PropertyType DWord -Value 0 -Force | Out-Null
Restart-Service ZfsWinUserMode

Use ReadOnly = 1 to look at a pool without changing a single byte. For a quick look without the service, run this from an elevated terminal with the service stopped. Ctrl+C unmounts and exports.

"C:\Program Files\OpenZFS for Windows (user mode)\bin\zfswin-um.exe" mount D:\pools tank tank/data Y: --readonly

6. Status and problems

  • Event Viewer > Windows Logs > Application: source WinFsp for mounts, unmounts and engine errors, and ZfsWinBroker for every administrative command.
  • Get-Service ZfsWinUserMode, ZfsWinBroker shows both services. Both restart by themselves after a failure.
  • zfswin pool status shows the health of each pool.

Uninstall

Use Settings > Apps. This stops the service, which unmounts and exports the pools, then removes the program. Your pools, your mount settings and WinFsp are kept.
