OpenZFS for Windows (user mode)

ZFS datasets as Windows drives, served by the ZfsWinUserMode service through WinFsp. No kernel driver of ours is involved, so this works with Secure Boot on.

WinFsp - Windows File System Proxy, Copyright (C) Bill Zissimopoulos, https://github.com/winfsp/winfsp.

1. What you need

  • A ZFS pool, on a disk or in image files. This edition does not create pools yet. Create them with the kernel-driver edition, or on Linux, FreeBSD or macOS with OpenZFS 2.4. The pool must be exported there first (zpool export).
  • WinFsp 2.1 or later. Setup refused to install without it.

2. Mount a dataset

The easy way: start OpenZFS for Windows (user mode) from the Start menu. On its User mode tab you can add, edit and remove mounts and start, stop or restart the service. It needs the .NET 10 Desktop Runtime; Windows offers it if it is missing. The other tabs (pool features, mirrors, caches) need the kernel-driver edition.

By hand:

In PowerShell as administrator, describe the mount once. It is mounted every time the service starts, including at boot:

$key = "HKLM:\SOFTWARE\OpenZFS for Windows\UserMode\Mounts\tank"
New-Item -Force $key | Out-Null
Set-ItemProperty $key Source     'D:\pools'          # folder with the pool's image files (whole disks: not tested yet)
Set-ItemProperty $key Pool       'tank'
Set-ItemProperty $key Dataset    'tank/data'         # the file system to show
Set-ItemProperty $key MountPoint 'Z:'                # a free drive letter, or a folder path that does not exist yet
New-ItemProperty $key -Name ReadOnly -PropertyType DWord -Value 0 -Force | Out-Null
Restart-Service ZfsWinUserMode

Drive Z: then appears, with the file system name ZFS. Add one key per dataset. Use ReadOnly = 1 to look at a pool without changing a single byte.

3. Use it

Use the drive like any other: Explorer, copy and paste, robocopy, applications. Writes are safe on disk after an application flushes, after a write-through write, or once the service stops. That is the same promise as any Windows drive. A power cut does not corrupt the pool: ZFS is always consistent on disk.

4. Unmount and move the pool

Stop-Service ZfsWinUserMode

This unmounts every dataset and exports the pools, so you can take the disk or image files to another computer. Linux, FreeBSD, macOS or the kernel-driver edition then imports them. To stop mounting one dataset, delete its key under Mounts and restart the service.

5. A quick look without the service

From an elevated terminal, with the service stopped:

"C:\Program Files\OpenZFS for Windows (user mode)\bin\zfswin-um.exe" mount D:\pools tank tank/data Y: --readonly

Ctrl+C unmounts and exports. zfswin-um --version prints the version.

6. Status and problems

  • Event Viewer > Windows Logs > Application, source WinFsp, records every mount, unmount (with the export result) and error, such as "cannot import …".
  • Get-Service ZfsWinUserMode shows the service state. It restarts by itself after a failure.
  • If the drive does not appear, check that Source contains the pool, that the pool was exported elsewhere, and that the drive letter is free.

Uninstall

Use Settings > Apps. This stops the service, which unmounts and exports the pools, then removes the program. Your pools, your mount settings and WinFsp are kept.
