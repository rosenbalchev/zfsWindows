# Step 03 — Pool recognition and uberblock selection

Status: `in progress`

Objective: recognize genuine OpenZFS raw vdev images and select a valid
uberblock without writing to the image.

Implementation:

- decode label nvlist with bounds and endian checks;
- validate pool and vdev GUIDs, ashift, topology, and feature flags;
- scan uberblock rings and select the highest valid transaction group;
- verify uberblock checksums and reject unsupported metadata safely;
- expose pool identity and unsupported-feature diagnostics in the C ABI.

Evidence: fixtures generated by official OpenZFS tools; selected uberblock
matches independent upstream inspection; image hash unchanged.

Current result: the ABI now reports valid top-level label identity, vdev
labels, uberblock candidates, the highest TXG, and read-only recognition for
an exported OpenZFS 2.4.1 single-file-vdev fixture. The fixture was created in
the disposable Ubuntu Hyper-V VM with official `zpool` tools, exported, copied
to `TestVolumes/step03-pool.raw`, and verified unchanged by SHA-256 during the
Windows integration test. Plain raw files remain rejected.

Remaining work before completion: recursively decode `vdev_tree`, validate
actual nested `ashift` and topology, enumerate supported/unsupported feature
flags, and verify the selected uberblock's root block pointer/checksum rather
than relying on its magic and nonzero TXG.

Commit: `native: recognize pools and validate uberblocks`
